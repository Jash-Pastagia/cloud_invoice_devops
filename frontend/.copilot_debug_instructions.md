# Frontend Debug Instructions - React Error #31 Fix

## Overview
This document provides debugging steps for React "Minified React error #31" (invalid element type) that was affecting the Invoices page.

## Fixed Issues

### 1. Object Rendering in JSX
**Problem**: Direct rendering of objects in JSX causes React error #31
```jsx
// ❌ WRONG - This causes error #31 if customer is an object
<td>{invoice.customer}</td>

// ✅ FIXED - Safe rendering with type checking
<td>{safeRenderCustomer(invoice.customer)}</td>
```

### 2. JWT Decode Import Issue
**Problem**: Incorrect import syntax for jwt-decode library
```javascript
// ❌ WRONG - Old import style
import jwtDecode from 'jwt-decode'

// ✅ FIXED - New named import
import { jwtDecode } from 'jwt-decode'
```

### 3. Missing dayjs Plugin
**Problem**: dayjs relativeTime plugin not imported
```javascript
// ✅ ADDED - Proper plugin setup
import dayjs from 'dayjs'
import relativeTime from 'dayjs/plugin/relativeTime'
dayjs.extend(relativeTime)
```

## Common React Error #31 Patterns to Avoid

### 1. Direct Object Rendering
```jsx
// ❌ WRONG
{someObject}

// ✅ RIGHT
{someObject?.name || 'N/A'}
{safeRender(someObject)}
```

### 2. Invalid Component Imports
```jsx
// ❌ WRONG - Module object used as component
import * as MyComponent from './MyComponent'
<MyComponent />

// ✅ RIGHT - Proper default import
import MyComponent from './MyComponent'
<MyComponent />
```

### 3. Undefined Components
```jsx
// ❌ WRONG - Can cause element type invalid error
const MyComponent = undefined
<MyComponent />

// ✅ RIGHT - Check before rendering
{MyComponent && <MyComponent />}
```

### 4. Dynamic Components
```jsx
// ❌ WRONG - Object used as component
const componentMap = {
  type1: { name: 'Component1' }
}
const Component = componentMap[type]
<Component />

// ✅ RIGHT - Function components
const componentMap = {
  type1: Component1
}
const Component = componentMap[type]
{Component && <Component />}
```

## Preventive Measures

1. **Use TypeScript** (future enhancement) - Catches type errors at compile time
2. **ESLint Rules** - Add rules to prevent object rendering
3. **PropTypes** - Runtime prop validation in development
4. **Safe Utilities** - Always use `safeRender()` functions for dynamic data
5. **Error Boundaries** - Wrap components to prevent app crashes
6. **Development Logging** - Use devUtils for debugging

## Production Considerations

- Error boundaries log errors for monitoring
- Safe rendering functions have minimal performance impact
- Development utilities are disabled in production builds
- Consider adding error reporting service (Sentry, etc.)
